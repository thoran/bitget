2. ~ test/V2/client_test.rb --> test/V2/Client_test.rb. The same fault, and test/test_all.rb requires it by the upper case name.

# 20260820
0.6.0: + Bitget::Configuration, and logging per client instead of per class.
1. + Bitget::Configuration: api_key, api_secret, api_passphrase, debug and logger, with Bitget.configure, Bitget.configuration and Bitget.reset_configuration!. Settings had been per-client and per-class; they are now declared once and every client built afterwards reads them as its defaults.
2. ~ Bitget::V2::Client: logging is per instance. @debug and @logger are taken from the options or from Bitget.configuration, and use_logging? is now !@logger.nil? — logging happens when there is somewhere to log to, so a flag and a logger can no longer disagree. Every setting is read the same way: the credentials are named arguments falling back upon nil, and the rest are given under options: and fall back upon the key being absent, nil being a value a caller may mean for a logger. The host is not among them: it is one value for this API, poloniex.rb and eodhd.rb hold theirs as a constant too, and a setting for it is a lever which can only be pulled wrongly, a signed request carrying the secret to a host nobody meant.
3. - Bitget::V2::Client: the class-level log file machinery, being default_log_file_path, log_file_path, log_file and the class logger. Deciding where a log file lives, rotating it and creating its directory are the caller's, and it hands in whatever Logger it likes.
4. ~ Bitget::V2::Client#initialize: @logger was assigned through options.key?(:logger ? ... ) rather than options.key?(:logger) ? ... , so the ternary ran inside key? and @logger became false. The line above it, for @debug, has the parentheses right.
5. ~ Bitget::V2::Client: log_request, log_response and log_error called self.class.logger, which 3 had removed. They read the instance's logger.
6. ~ Bitget::Error: the body is parsed through a method which rescues JSON::ParserError and answers an empty hash. A 418 arrives with an empty body, and an error raised because something already went wrong must not fail to build and report a parsing problem in place of the real one.
7. ~ Bitget::Error#error_code and #error_message: fall back to the HTTP code and message where the body carries none, so that an error renders as something rather than as a pair of blanks.
8. - lib/Hash/x_www_form_urlencode.rb and lib/Thoran/Hash/XWwwFormUrlencode/x_www_form_urlencode.rb, and the require of the first. http.rb provides Hash#x_www_form_urlencode and this gem declares http.rb as a runtime dependency, so the vendored copies said the same thing twice.
9. ~ test/helper.rb: + require 'minitest/mock'. Minitest 5 loaded it by way of minitest/spec and Minitest 6 does not, so every test using a mock errored.
10. - test/client_test.rb, and its require from test/test_all.rb. The whole file, 198 lines of it, tested that Bitget::Client delegates to a Bitget::V2::Client held in @v2_client. Bitget::Client has been a subclass of Bitget::V2::Client since 0.1.0 and there has never been a @v2_client anywhere in lib, so the mock was set on nothing, the call ran through to a real request and VCR stopped it. They were written in 0.5.0 and shipped failing in the same commit. Inheritance is not a thing to assert, and the V2 suite already covers the methods against cassettes. Those 47 tests also carried no assertions between them: the run reports 871 either way.
11. ~ test/V2/client_test.rb: the logging tests drive an injected Logger.new(StringIO.new) and read its contents, in place of setting a use_logging flag and reading a file the client no longer writes. - the three which tested the log file path, its directory and its rotation, those being no longer the client's to do.
12. + test/V2/client_test.rb: that a request string is the scheme, the host, the version prefix and the path, written out rather than built from API_HOST and .path_prefix, which would pass however wrong either was; breaking the host takes the suite to 6 failures and 53 errors. + that the version prefix is /api/v2, that being what makes V2::Client a class of its own.
13. + test/Configuration_test.rb: the declared defaults, that a setting exists for everything a client reads, that each credential is supplied and each yields to what is given, that each option is supplied and each yields to what is given, and that nil under options: is taken as a value rather than as an absence.
14. + README.md: Configuration and Logging sections. 3 removes the built-in file logger, so the replacement is documented in the release which removes it: Logger.new(path, 'daily'' rotates by itself and wants only a FileUtils.mkdir_p first, which is the whole of what the client used to do for you.
15. ~ Bitget::VERSION: /0.5.0/0.6.0/
